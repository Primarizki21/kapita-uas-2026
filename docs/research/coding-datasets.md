# Public coding-problem datasets for a collaborative-debugging pivot

**Prepared:** 2026-11-23. **Scope:** public, downloadable data that could replace the "math word problem" role in SocioMathLLM, with the social module remapped to collaborative debugging. No self-built dataset; no GPU budget assumed.

**Verification key.** "Verified" below means the official repository/dataset card/licence/file was fetched directly on 2026-11-23, and the download URL returned HTTP 200. Hash values without an external link were computed here (`sha256sum`) from the pinned URL; HF LFS `oid` values were read from `https://huggingface.co/api/datasets/<id>/tree/<revision>?recursive=true&expand=true`. The SHA-256 values for DebugBench `eval.json` and EvalPlus `test.jsonl` were additionally confirmed by streaming the files and hashing locally. To verify any pinned file: `printf '%s  %s\n' '<sha256>' '<file>' | sha256sum -c -`.

**Property shorthand used in the table:** **S** = natural-language problem statement; **T** = executable tests bundled in the download; **B** = buggy code bundled in the download; **D** = explicit difficulty or grade label. ✓ = present, ~ = partial/indirect, ✗ = absent.

## Ranked shortlist for six students, no GPU

1. **ITSP** — the only compact (≈19 MB), MIT-licensed, fully local bundle that pairs a complete natural-language statement with a buggy **and** correct student solution plus input/output test files for the same problem (661 programs); lab ID is the sole difficulty proxy. No training, no GPU, and C compilation are all that is needed.
2. **DebugBench** — the best semantic match to the proposed pipeline: 4,253 rows contain `question`, `level`, `buggy_code`, `bug_explanation`, `solution`, and public `examples` in a 20 MB file; the penalty is that full test suites require a LeetCode session, so local scoring should be limited to `examples` [INFERENCE].
3. **IntroClass** — 998 authentic novice defects with human fixes and blackbox/whitebox tests in a 215 MB archive; ranked third because "statements" are only six one-line assignment descriptions and there is no difficulty label.

**Swap rule:** if an explicit difficulty label is mandatory, replace IntroClass with **TACO** (statement + tests + EASY…VERY_HARD, but no buggy code) or accept **CodeContests** (all four signals in the schema, but ~3 GiB and uncurated wrong submissions). For Indonesian-language statements, the only licence-cleared source found is **ia-toki/training-gate-id** (CC BY-NC-SA 4.0), but it is PDF/LaTeX material and would require self-conversion, which the public-data-only rule forbids.

## Explicit statement of missing properties

**No public dataset found provides, in one small downloadable artifact, all four of: a full natural-language problem statement, a fully local executable test suite, a curated single-defect buggy program, and an explicit difficulty/grade label.** The gaps are concrete:

- **ITSP, IntroClass, QuixBugs, ProgFeed** have buggy code and local tests; ITSP/ProgFeed have full statements, IntroClass has only one-line assignment descriptions, and QuixBugs has essentially no statement. None has an explicit per-item difficulty rating.
- **DebugBench** has statement, buggy code, difficulty, and a bug explanation, but its hidden tests are not in the download and require a LeetCode account/session ([HF card](https://huggingface.co/datasets/Rtian/DebugBench)).
- **APPS, TACO, LiveCodeBench, CodeContests** have statements, tests, and difficulty labels, but no curated single-defect buggy seed; CodeContests' `incorrect_solutions` are wrong human submissions that may not even compile ([README](https://github.com/google-deepmind/code_contests/blob/main/README.md), [proto](https://github.com/google-deepmind/code_contests/blob/main/contest_problem.proto)).
- **HumanEval, HumanEval+, MBPP, CodeXGLUE, CodeNet, idea-first, Sandroeth** each miss at least one of the four properties as detailed in the table.

**Decision implication.** If the team insists that all four properties must be present natively, no dataset qualifies and the already-decided fallback should be retained: **MathVista testmini, ChartQA + TabMWP (112 items)** ([MathVista HF dataset](https://huggingface.co/datasets/AI4Math/MathVista)). If the team accepts one documented substitution — lab ID or solve-rate tier as difficulty, or public examples in place of a full hidden suite — the coding pivot has viable public data, with ITSP as the primary choice.

## Manifest notes for the later ledger (no hashes invented)

Record, per selected item: dataset ID, pinned commit/revision, direct file URL, file size, SHA-256 from the table above, download date (2026-11-23 for these checks), licence, and which of S/T/B/D the source natively supplies. Anything produced by mutating a correct solution into a buggy one, or by writing a new scenario, is a **derived experiment artefact**, not source data [INFERENCE]; disclose it explicitly rather than presenting it as a dataset contribution. Never place API keys in the manifest or repository.
