# Public datasets for debugging and for the social side of debugging — evidence review

**Verification date: 2026-11-23.** Scope: public, downloadable data only; no self-built dataset. This review answers whether the team can move the SocioMathLLM replication from math word problems to *coding problems with collaborative debugging* while keeping the paper's social component grounded in an existing public dataset.

## Verification key and method

- **[V-GET]** official URL fetched directly with HTTP 200 on 2026-11-23 (page/README/CSV/file listing).
- **[V-API]** official API returned metadata on 2026-11-23 (GitHub REST, Hugging Face Datasets API, Zenodo API, Figshare API).
- **[V-DOI]** DOI resolved via `https://doi.org/…` on 2026-11-23. ACM DOIs returned HTTP 403 to automated HEAD requests (anti-bot), so those are verified through OpenAlex plus the official publisher/PDF page and are marked **[V-DOI:403/OpenAlex]**, not treated as broken.
- **[V-WEB]** claim found via web search on 2026-11-23 with an official source cited, but not re-fetched byte-for-byte here.
- **[UNVERIFIED]** no public license, no public download, no published hash, or contents not machine-checked. These are flagged explicitly; nothing is inferred into existence.
- **[INFERENCE]** my analytical judgement, not a dataset fact.

Literature search commands actually run on 2026-11-23: `mcp__openalex_search_works --query '<primary paper title>' --per-page 3` and `mcp__mendeley_search_catalog '<primary paper title>' --limit 3`. OpenAlex returned explicit DOI strings for all primary papers listed below. Mendeley's global catalog returned matching titles and years (e.g. CodeXGLUE catalog ID `552b4478-2ebc-3b3a-b916-20b5b20e1d0d`) but its `identifiers` object did **not** expose a DOI field for these records [V-API]; therefore DOIs reported below come from OpenAlex and are cross-checked against DOI.org / official publisher or repository pages. Mendeley match status is recorded per DOI; no DOI is attributed to Mendeley alone.

## Direct answer to the availability question

**No.** I found **no public dataset that jointly provides (i) buggy code, (ii) multi-person debugging dialogue with turn/author structure at usable scale, and (iii) explicit social/interaction labels** that could replace SocioMathLLM's socialisation module. This is an **[INFERENCE]** based on the two tables above and the documented contents of every candidate.

Closest alternatives and why each is insufficient:

1. **Disc-BFP** (3,028/3,333 examples) is the only released corpus that explicitly pairs a buggy method, a fix, and issue discussion preceding the fix [S30,S31]. Limitation: ≈2.8–2.9 utterances per example, no role/dialogue-act/social labels, Java methods only, no licence, Google-Drive-only distribution.
2. **Chromium Conversations** (≈1.5M comments, 1.48M conversations, 4,842 speakers) is the largest true multi-person developer discussion corpus with an "acted-upon" label and reviewer/developer roles [S26,S27]. Limitation: review feedback on proposed patches, not debugging sessions; no buggy-code snapshot or bug labels; CC BY 4.0 with 1.1 GB CSV.
3. **CodeReviewer** supplies diff → reviewer comment → revised code at enormous scale [S28,S29]. Limitation: single-comment records, no multi-turn dialogue, no social labels, no "bug" ground truth.
4. **SWE-bench** supplies executable buggy repository states plus issue text (2,294 tasks; 500 Verified) [S14–S16]. Limitation: `hints_text` is a flattened comment field, not a dialogue; no social competencies; licence metadata incomplete.
5. **GitHub Agentic PR Dataset** has PR review threads and patches (CC BY 4.0) [S32]. Limitation: heterogeneous, post-hoc comments, no debug/social annotation, 1.55 GB+ files.
6. **COMPS** has the near-exact social label taxonomy — sharing ideas, negotiating ideas, regulating problem solving, maintaining communication — in a Java programming class [S20,S21]. Limitation: **no public download or licence found**; annotated subsets are 1,280–1,395 turns; the labelled discussions concern code analysis rather than documented bug repair.
7. **Figshare pair-programming corpora** provide 40,490 inclusive/exclusive/neutral labels [S23] and 42,820 micromanagement/good-collaboration/irrelevant labels [S24] on real student talk. Limitation: no buggy code, no debugging task ground truth, very imbalanced positive classes.
8. **Madeline corpus** provides 2,459 debugging speech-act annotations [S25]. Limitation: one developer plus a Wizard-of-Oz assistant, not multi-human; no explicit licence or hash-pinned public archive.

**Project-level consequence [INFERENCE]:** because the requested pivot requires a public dataset with buggy code *and* collaborative social signal, and none exists at usable scale, the already-decided fallback (MathVista testmini ChartQA+TabMWP, 112 items) should be retained rather than substituting a weak proxy or constructing a new dataset. If the team later changes the public-data constraint, Disc-BFP + COMPS-style labels would be the strongest hybrid design, but that would be self-built annotation and is outside the current brief.
